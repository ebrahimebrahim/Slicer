# pyproject.toml support — rationale summary

We added `load_pyproject_dependencies()` as a sibling to `load_requirements()`. It reads `[project.dependencies]` from a pyproject.toml via `tomllib` (stdlib) and returns the same `list[Requirement]`, so the downstream API (`pip_check`, `pip_ensure`) works identically with either format. Extensions can use whichever they prefer. The `requirements.txt` path remains the primary recommendation since extensions aren't Python packages and it requires no boilerplate, but pyproject.toml is there for extensions that want the modern standard. Adopting uv is a separate decision from the file format and is out of scope for this PR.
